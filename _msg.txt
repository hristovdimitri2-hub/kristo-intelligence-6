fix(stripe): send the product tax code Managed Payments requires

The Managed-Payments fallback landed the request one step further and Stripe
named the next requirement in full:

  POST /v1/checkout/sessions -> 400
  Unsupported parameter: payment_method_types. ... Remove payment_method_types,
  or pass managed_payments[enabled]=false to disable it ...
    -> retried without it -> 400
  Invalid line_items[0]: the product tax code is missing. Set the product's
  tax_code field to an eligible product tax code

Managed Payments makes Stripe the MERCHANT OF RECORD (VAT/sales tax in 80+
countries, BG is a supported country), so the right move is to satisfy it rather
than disable it. Every line item now carries product_data.tax_code =
txcd_10000000 ("General - Electronically Supplied Services"), an eligible code
for exactly what we sell and the honest one for a mixed business/personal buyer
base. STRIPE_PRODUCT_TAX_CODE overrides it without a code deploy.

The parameter handling is now a small chain - full, then without
payment_method_types (tax code kept: Managed Payments needs it), then without the
tax code too - and each step is taken ONLY when Stripe's message names the
parameter that step removes. A "tax code is missing" answer is a reason to SEND
it, never to drop it, and every unrelated error still fails on the first call.

TESTS 276 -> 278: the tax code default + override, and the chain (3 calls, step 2
keeps the code, step 3 drops it, a missing-code error never walks step 3).
