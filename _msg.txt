fix(stripe): the two Managed Payments blockers + a readiness tool

The owner switched to the newly activated live account and asked for the final
check. The health check went green (acct_1UFfUcPz7WIGP94b, charges_enabled True,
card_payments active, exit 0), but the checkout still answered 503 - and our own
log (the 14.09 diagnosability fix) named the reason exactly, twice in a row:

  400 Unsupported parameter: payment_method_types. Managed Payments, which is
      enabled by default on your account, handles this parameter for you.
      Remove payment_method_types, or pass managed_payments[enabled]=false ...
  -> retried without it ->
  400 Invalid line_items[0]: the product tax code is missing.

The new account runs MANAGED PAYMENTS (Stripe as merchant of record: VAT/sales
tax in 80+ countries, BG supported), so the answer is to satisfy it, not to
disable it:

  * payment_method_types is now a FALLBACK parameter, not a constant: the
    parameters are tried as a chain (full -> without payment_method_types, tax
    code kept -> without both) and each step is taken ONLY when Stripe's message
    names the parameter that step removes. Every other error still fails on the
    first call, so a real failure is never retried blindly.
  * every line item now carries product_data.tax_code = txcd_10000000 (General -
    Electronically Supplied Services, eligible for a fully automated digital
    service), overridable with STRIPE_PRODUCT_TAX_CODE.

Evidence: POST /sales/checkout -> 303 -> cs_live_... verified at Stripe at
$29.00 usd, livemode=true. Tests 274 -> 278.

Also in this commit, because the same check found it: the account has ZERO
webhook endpoints (the whsec_ in Render belongs to the OLD account's endpoint, and
a key and its signing secret never travel together). stripe_health.py now shouts
when the endpoint list is empty, and scripts/stripe_readiness.py asks the whole
question in one command - account, checkout verified at Stripe, and a REAL
delivery observed in our own log - with exit 0 only when all three are green.
