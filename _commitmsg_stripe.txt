Stripe: a mock checkout worked in production, and a typo billed the Pro price

1. KRISTO_ALLOW_MOCK_PAYMENTS WORKED IN PRODUCTION
   A mock checkout is a session that unlocks a paid product with no money
   moving, so the flag alone is a footgun: one env var typed into a production
   dashboard grants free access to every human product. `_mock_payments_allowed`
   now refuses whenever the process is the live service, detected from the
   platform markers (RENDER, RENDER_SERVICE_ID) rather than from our own config
   — a missing or mistyped APP_ENV cannot silently turn the check off. Locally
   and in tests the flag still works, because the flow depends on it.

2. AN UNKNOWN plan_key CHARGED THE PRO PRICE
   `_plan_amount` fell back to PLAN_PRICES["pro"] for any unknown key, so a
   mistyped or removed plan silently produced a $79 invoice and nothing said so.
   An unknown plan now raises, and `create_checkout_session` returns it as
   checkout_error / unknown_plan — a refusal, not a 500 and not a wrong invoice.
   The agent-catalog path is unaffected: it passes amount_usd explicitly.

3. int(resolved_amount * 100) TRUNCATED INSTEAD OF ROUNDING
   Safe for 29/79/149, but 0.29 or 1.15 would come out a cent short. Now
   int(round(...)).

4. VERIFIED: the agent checkout amount comes from the SERVER
   The audit could not tell where `amount_usd` came from in
   create_catalog_checkout_session. It comes from `agent["price_stripe"]` via
   catalog_store.get_product(agent_id) — the server catalog, not the request
   body. There is no price-manipulation hole there.
