The board could not heal itself after the process started — and three handles leaked

Measured 12.11: /api/dashboard/data answered 500 with an EMPTY cache and

    dashboard: background refresh failed ... database disk image is malformed

The local SQLite file had gone bad AFTER the process started. The boot-time heal
had already run and had nothing to complain about, so every build from then on
failed, no payload was ever published, and the board stayed 500 for the life of
that process. A restart would have cleared it; nothing else would.

1. THE HEAL IS NOW CALLABLE AT RUNTIME. `DashboardStore.heal_local_store()`
   quarantines the bad file and recreates it, and `_dashboard_build` catches
   `LOCAL_STORE_ERRORS`, heals and retries EXACTLY ONCE. `LOCAL_STORE_ERRORS` is
   exported from the store so the web layer does not have to import `sqlite3` to
   spell the dialect's exceptions itself. A second failure still propagates: a
   board that cannot build must say so rather than serve an empty success.

2. THREE CONNECTIONS LEAKED, AND THAT IS WHY THE HEAL WOULD NOT HAVE WORKED.
   Exercising it exposed `WinError 32` — `os.replace` cannot move a file another
   handle holds open — and every leak was real:

     DashboardStore._connect() used as `with self._connect() as conn:` (4 sites)
       sqlite3.Connection.__exit__ commits, it does NOT close.
     HistoryStore._run's sqlite branch, same shape.
     HistoryStore._ensure_column opened a probe connection per migrated column on
       every boot and never closed it at all.

   On Linux an open handle is only a leak; on Windows it makes the heal
   impossible, which is the difference between a board that recovers by itself
   and one that needs a human. `DashboardStore._local()` is a context manager
   that actually closes, and the other two sites now close explicitly.

Four tests in tests/test_dashboard_local_heal.py: the store heals after going bad
mid-life, the build heals and retries exactly once, a second failure is not
swallowed, and a Postgres error does NOT quarantine a healthy local file.
