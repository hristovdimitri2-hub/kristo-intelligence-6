CI: there was no pipeline at all

The only check before a change reached the live service was running the suite by
hand on one machine. Adds .github/workflows/ci.yml and .github/dependabot.yml.

Job `tests`: Python 3.12, installs requirements-dev.txt (the runtime set plus
pytest — the deploy file no longer carries a test runner, so a pipeline that
installed only that would die at `pytest: command not found`), runs `pytest -q`.

Job `secrets`: gitleaks over the WORKING TREE (--no-git), not the history. That
is deliberate. The gate is "do not COMMIT a credential", not "audit every commit
ever made": the history is known to contain older material and rewriting it is a
destructive decision the owner has not taken, so a job that failed on day one
and could not be fixed without a force-push would be noise rather than signal.
When the history is clean, dropping --no-git makes it the full audit.

Dependabot: weekly for pip (grouped into one PR), monthly for GitHub Actions and
for the packages/x402-client npm package. cryptography signs the CDP JWT and
web3 moves the money, so a CVE in either is not housekeeping.

Test: test_the_pipeline_installs_the_dev_file_and_says_what_it_scans guards both
halves — that the pipeline installs the dev file, and that the scan names its
scope.
