Redact credentials on every persisted path, not only in the log

redact_rpc() existed and the log lines used it, but eight places wrote the
SAME exception unredacted into state that is then served publicly. The
clearest pair is the dashboard warmer: line 8792 logs redact_rpc(exc) and
line 8794 wrote str(exc)[:120] into _organism_beat, whose detail field is
published in sections.organism.blocks[].detail on /api/dashboard/data
(confirmed live). The leak was latent — the last scans did not fail — but
the first scan failure carrying a keyed RPC URL would have persisted the
credential in Postgres and republished it.

Fixed sites: main.py 1741, 5848, 5889, 5972, 5996, 6299, 6394, 8794, 8922;
src/nexus/nexus_core.py 177 (the public activity page's source report).

Also widened redact_rpc: it masked RPC keys (/v2/<KEY>, apikey=, token=) but
not connection URLs, where the credential is the password half of
scheme://user:pass@host. A psycopg or redis exception echoes the DSN it
failed to reach, so an unredacted one publishes the database password. The
new rule keeps user and host and drops the password; a bare URL with no
credential is untouched.

Redact before truncating, never after: cutting first can leave half a key.
