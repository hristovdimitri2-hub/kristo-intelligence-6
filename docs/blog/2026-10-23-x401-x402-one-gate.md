# One gate: chaining x401 identity with x402 payment in a single round-trip

**Kristo Intelligence · 23 October 2026 · MIT · Status: design proposal**

## The gap everyone is talking about

On 21 October, PayAI posted what many of us have been thinking:

> "x401 answers 'who is this agent acting for?' x402 answers 'did it pay?'
> Nobody's shipped the one-line middleware that chains both: verify the human
> behind the agent, then take payment. Age-gated data, regulated APIs, KYC'd
> services. One gate."

We run Kristo Intelligence — an x402-gated API on Base — and we've had the
same KYC-attestation idea queued for our next milestone. Before writing code,
here is the design, open for scrutiny.

## The problem with the obvious flow

Taken separately, x401 and x402 cost two round-trips:

1. `401` + `PROOF-REQUIRED` → agent presents credential → request again
2. `402` + `X-PAYMENT` → agent pays → request again → `200`

Worse, the two handshakes are **unrelated**: the identity proof proves *someone
is present*, the payment proves *someone paid* — nothing cryptographically ties **who** to **this transaction**.

## The design: one response, two challenges

Return both challenges in a **single** response:

```
HTTP/1.1 402 Payment Required
X-PAYMENT: <amount, asset, recipient, network>
PROOF-REQUIRED: <credential type, required claims, nonce>
```

The agent answers once:

```
X-PAYMENT: <payment payload>
PROOF-PRESENTATION: <OpenID4VP/DCQL presentation>
```

Server verifies presentation + settles payment in parallel → `200` + receipt.
One round-trip, one gate.

## The actual innovation: bind the challenge to the payment

The `PROOF-REQUIRED` nonce **is the payment parameters** (amount, asset,
payTo, network). The human's signed mandate therefore authorizes *this exact
transaction* — not "the agent exists", but "this person approves spending $X
to this recipient, right now".

## The receipt: non-repudiable authorization record

The settlement record binds:

```
settlement tx hash  ↔  verified credential subject  ↔  payment challenge nonce
```

Result: a durable, independently verifiable proof that **this verified subject
authorized this payment**, settled on-chain. That is the record regulated and
age-gated services actually need.
