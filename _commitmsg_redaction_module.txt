Redact at the raise site: move the scrubber to a dependency-free module

Independent confirmation of the defect class fixed in 3a26d29. In the x402
Foundation's github-discussions channel, Lena Hierzi (Celo) reports x402-rs
#115/#118: "the RPC URL, which carries the provider's API key, leaks into the
startup log and into verify/settle error bodies. On a public facilitator that's
an API key in a response any buyer can read." Same shape as ours: the secret is
in the message, and the message travels.

Checked our own verify/settle path first. It is clean:
  * services/seller_audit.py:213 returns only type(exc).__name__, never the text
  * main.py:1076 redacts before storing _wallet_state["rpc_error"]
  * the success receipt carries network eip155:8453, and we emit no failure
    receipt at all, so x402-rs #119 (empty network on failure) does not apply

But one trap remained. blockchain/wallet.py:97 and services/base_listener.py:53
raised ConnectionError(f"Cannot connect to Base RPC at {rpc_url}") — the raw
URL, with the provider's key in it, inside the exception text. Today's only
caller wraps it; the next one should not have to remember.

The scrubber lived in integrations/dashboard_store.py, which is heavy (sqlite3,
psycopg, the whole store), so the low layers could not import it without
dragging the store along. Moved it to redaction.py — standard library only — and
re-exported it from dashboard_store so every existing import path and test keeps
working. src/nexus/nexus_core.py now imports the light module too.

Both raise sites now redact where the text is created. The host stays visible so
the error is still diagnosable; only the key is dropped.

Test: test_rpc_key_is_redacted_where_the_exception_is_created asserts the
scrubber output and that both modules reference redact_rpc(rpc_url) at the raise
site, so a future edit that reintroduces the raw URL fails the suite.
