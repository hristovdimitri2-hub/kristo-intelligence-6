Dependencies: pytest was a production package, cryptography was unpinned

requirements.txt is what the deploy installs (Dockerfile, DEPLOYMENT.md,
DEPLOYMENT_CHECKLIST.md). It had two defects.

1. pytest WAS A PRODUCTION DEPENDENCY
   Every production image shipped a test runner it never ran. Moved to a new
   requirements-dev.txt, which starts with `-r requirements.txt` so a dev
   install still gets the runtime dependencies.

2. cryptography>=42.0.0 — UNPINNED, AND UNDER THE WRONG HEADING
   It is a RUNTIME dependency: services/connectors.py signs the CDP Platform
   JWT with it (ES256 / secp256r1). It sat as `>=` under a "Testing" heading,
   which was wrong twice: the deploy installed whatever pip resolved that day,
   and the heading told a reader it was a dev dependency. It is now
   cryptography==48.0.0 (matching the lock) in its own "Crypto / signing"
   section.
