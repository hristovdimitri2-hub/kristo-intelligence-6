Dependency bumps: apply the minor updates Dependabot proposed, lock included

After the ignore rules stopped major versions, Dependabot opened two more PRs —
#8 (the 5-package runtime group) and #7 (pytest). BOTH still failed, and no
longer because of web3: because of requirements.lock.

test_every_exact_pin_agrees_between_the_two_files compares requirements.txt with
the lock. Dependabot edits only the first, so every PR it opens leaves the lock
behind and the test fails — correctly. The guard from the previous commit did
exactly the job it was written for, on its first real PRs.

Applied by hand, because Dependabot cannot update the lock:
  gunicorn        26.1.0 -> 26.2.0
  stripe          15.5.1 -> 15.6.2
  psycopg[binary]  3.3.4 -> 3.3.8
  python-dotenv    1.2.3 -> 1.2.4
  pytest (dev)     9.1.1 -> 9.2.0
requirements.txt, requirements-dev.txt and requirements.lock are updated
TOGETHER — otherwise the PR stays red.

VERIFIED, NOT ASSUMED: the new versions were installed into the venv and the
full suite was run — 1388 passed, 1 skipped. PyPI metadata was also checked, so
no new version pulls a dependency that is missing from the lock (gunicorn and
python-dotenv have no base deps; stripe wants typing_extensions + requests;
psycopg wants typing-extensions + psycopg-binary — all already in the lock).

Why this is safe where web3 8.0.0 was not: these are patch/minor releases of
packages whose interfaces we do not touch, while web3 was a MAJOR release of the
library that signs and broadcasts transactions. web3 stays ignored for majors.
