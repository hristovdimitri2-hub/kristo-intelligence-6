CI's first runs failed — and that was the useful part

The first four CI runs (on the Dependabot PRs) failed. `Test suite` passed on
every one of them, so the test job works. `Secret scan (working tree)` failed.
Its logs require admin rights, so I downloaded gitleaks and scanned an export of
the tracked files — exactly what CI sees.

19 findings. NOT ONE IS A SECRET. Every one is public by design:

  9  Base USDC contract + our receiver — public on-chain identifiers, printed
     in every 402 response
  3  keccak event topics (Transfer, AuthorizationUsed) — protocol constants
  2  the IndexNow key — it MUST be served at /<key>.txt or the check fails
  1  the agenteconomy domain-control token — it MUST be served from
     /.well-known/ or the claim quietly expires
  1  Lazaretto's signed public attestation — a proof published at
     lazaretto.dev/report/…, it grants nothing
  3  a placeholder hostname and the deliberate fakes the redaction tests assert on

The fix is NOT to switch the scan off. Adds .gitleaks.toml which extends the
default rules (useDefault = true), redefines no rule, and allowlists VALUES —
each with a comment saying why it is not a secret.

One detail worth remembering: the address patterns carry (?i), because the SAME
address is written checksummed in the 402 and lowercased in comparisons. The
first version of the allowlist caught 17 of 19 and missed exactly the two places
where the address is lowercase.

Why NOT allowlist "any 0x… 64 hex": a private key and a transaction hash look
identical, so a blanket hex rule would hide a real leak. The allowlist names
specific addresses and topics instead.

Verified locally: with the config gitleaks reports "no leaks found", exit 0
(before: 19 findings, exit 1).

Test: test_the_secret_scan_config_explains_every_exemption keeps the config from
becoming a blanket exemption — it requires useDefault, forbids [[rules]], and
requires every allowlist to carry a description.
